# NTPC-MUNPL GPS Tracking System — Deployment Guide

> **Target**: Windows Server with MS SQL Server already installed.  
> **Estimated setup time**: 30–45 minutes.

---

## Prerequisites

Install the following on the NTPC server before proceeding:

| Tool | Version | Download |
|------|---------|----------|
| Node.js (LTS) | 20.x or 22.x | https://nodejs.org |
| PM2 (process manager) | Latest | `npm install -g pm2` |
| pm2-installer (Windows Service) | Latest | `npm install -g @jessety/pm2-installer` |
| MS SQL Server | Any edition (Express is fine) | Already on NTPC server |

---

## Step 1 — Build and Copy Project to Server

1. **Build the frontend assets** in your development environment first:
   ```powershell
   npm run build:frontend
   ```
   This compiles and places the static dashboard/tracker files inside `backend/public/`.

2. **Copy the project folder** to a permanent location on the server.  
   **Recommended path:** `C:\ntpc\gps-tracking-system\`

```
C:\ntpc\gps-tracking-system\
  ├── backend\
  │     ├── data\          ← SQLite DB (autogenerated)
  │     ├── public\        ← Built frontend files (autogenerated via build step)
  │     ├── server.js
  │     ├── package.json
  │     ├── .env           ← you create this inside backend/ (see Step 2)
  │     └── ...
  ├── frontend\            ← Frontend source files (optional on server)
  ├── server.js            ← Backward-compatibility redirect shim
  ├── package.json         ← Root config
  ├── ecosystem.config.js  ← PM2 configuration pointing to backend/server.js
  ├── scripts\
  └── ...
```

> **Do NOT include any `node_modules\` or SQLite database `data\` directories** when copying — they will be regenerated/reinstalled automatically on the server.

---

## Step 2 — Configure the Environment

1. Copy the environment template inside the `backend` folder:
   ```powershell
   cd C:\ntpc\gps-tracking-system
   Copy-Item backend\.env.production.example backend\.env
   ```

2. Open `backend\.env` in Notepad and fill in **every value**:

   ```env
   PORT=3000
   NODE_ENV=production
   
   # The server's fixed LAN IP or hostname — this goes into QR codes
   SERVER_PUBLIC_URL=http://10.x.x.x:3000
   
   # Google Maps API key (from Google Cloud Console)
   GOOGLE_MAPS_API_KEY=AIza...
   
   # SQL Server connection
   MSSQL_SERVER=localhost          # or the SQL Server hostname
   MSSQL_PORT=1433
   MSSQL_DATABASE=gps_tracking     # will be created automatically
   MSSQL_USER=sa                   # or a dedicated user
   MSSQL_PASSWORD=YourRealPassword
   MSSQL_ENCRYPT=false
   MSSQL_TRUST_SERVER_CERTIFICATE=true
   
   HISTORY_RETENTION_DAYS=90
   ```

   > **`SERVER_PUBLIC_URL`** is the most important setting.  
   > It must be the IP/hostname that **tracker phones can reach**.  
   > If the server IP is `10.1.2.100`, set `SERVER_PUBLIC_URL=http://10.1.2.100:3000`.

## Step 3 — Prepare the SQL Server Database

1. Open **SQL Server Management Studio (SSMS)** on the server.
2. Create the database (the app will create tables automatically):
   ```sql
   CREATE DATABASE gps_tracking;
   GO
   ```
3. If using a non-`sa` user, grant permissions:
   ```sql
   USE gps_tracking;
   CREATE USER gps_user FOR LOGIN gps_login;
   ALTER ROLE db_owner ADD MEMBER gps_user;
   GO
   ```
4. Make sure **TCP/IP is enabled** in SQL Server Configuration Manager:
   - Open SQL Server Configuration Manager
   - SQL Server Network Configuration → Protocols → Enable TCP/IP
   - Restart SQL Server service

## Step 4 — Install Dependencies

Open **PowerShell as Administrator** in the project folder:

```powershell
cd C:\ntpc\gps-tracking-system

# Install only production dependencies (no dev tools)
npm install --omit=dev
```

## Step 5 — Test the Server Manually (Optional but Recommended)

Before installing as a service, do a quick sanity check:

```powershell
# Start manually
node server.js
```

Look for output like:
```
════════════════════════════════════════════════════════════
   NTPC-MUNPL GPS TRACKING SYSTEM  ·  PORT 3000
════════════════════════════════════════════════════════════
   Database ready  →  C:\ntpc\gps-tracking-system\backend\data\gps_history.db
   MS SQL Server client connected successfully!
   ✅  PUBLIC SERVER CONFIGURED
   📱  TRACKER URL  →  http://10.x.x.x:3000/tracker.html
```

Then visit `http://localhost:3000` in a browser on the server. If the dashboard loads — you're good.

Press `Ctrl+C` to stop.

---

## Step 6 — Install as a Windows Service (Auto-start on Boot)

Run the install script **as Administrator**:

```powershell
# Right-click > Run as Administrator
scripts\install-service.bat
```

This will:
1. Start the app via PM2
2. Save the process list
3. Configure PM2 to auto-start on Windows boot

Verify:
```powershell
pm2 status
```
You should see `ntpc-gps` in the **online** state.

---

## Step 7 — Allow Port 3000 Through Windows Firewall

```powershell
# Run as Administrator
netsh advfirewall firewall add rule `
  name="NTPC GPS Server" `
  dir=in `
  action=allow `
  protocol=TCP `
  localport=3000
```

---

## Step 8 — Verify Everything Works

From any device on the **same LAN**:
1. Open a browser → `http://<SERVER_IP>:3000/`  → Dashboard should load
2. Open a phone browser → `http://<SERVER_IP>:3000/tracker.html` → Tracker page
3. Hit the health endpoint: `http://<SERVER_IP>:3000/health` → should return `OK`

## Troubleshooting

### MSSQL connection fails
- Check credentials in `.env`
- Verify TCP/IP is enabled in SQL Server Configuration Manager
- Try connecting with SSMS using the same credentials first

### Dashboard shows no map
- `GOOGLE_MAPS_API_KEY` is blank or invalid in `.env`
- Visit the dashboard → it will prompt you to enter the key via the UI

### QR code shows wrong IP
- `SERVER_PUBLIC_URL` in `.env` is wrong or not set
- Restart the server after fixing it — QR is regenerated on startup

### Trackers can't connect
- Check firewall — port 3000 must be open
- Make sure `SERVER_PUBLIC_URL` uses the server's actual LAN IP, not `localhost`

### Port 3000 already in use
- Change `PORT=3000` to `PORT=3001` in `.env`
- Update `SERVER_PUBLIC_URL` accordingly
- Update firewall rule

---

## Security Notes

- This system is designed for **internal NTPC LAN use only**.  
- The dashboard has **no login** — keep it behind the LAN firewall.  
- Never expose port 3000 directly to the internet without a reverse proxy and HTTPS.
- The `.env` file contains credentials — do not share or commit it.
